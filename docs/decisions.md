## Decided
| # | Decision | Why | Date |
|---|---|---|---|
| A1 | Build our own system rather than buy a SaaS tool | User's call: build, but copy what the commercial tools do best | 2026-11-03 |
| A2 | Multi-client from day one (per-client isolation) | Several clients now, more coming | 2026-11-03 |
| A3 | Cut time across the whole pipeline, not one step | User's call | 2026-11-03 |
| A4 | Own the workflow and the publishing: our own platform apps and drivers behind a `Publisher` adapter; no paid aggregator | User's call at kickoff (replaces the research recommendation to rent publishing); the adapter keeps each platform a separate driver | 2026-11-03 |
| A5 | Platforms: Instagram, Facebook, TikTok and Google Business Profile, all four in the MVP; no other platform, now or later | User's call (replaces the research recommendation of TikTok in Phase 2); TikTok posts are private-only until our audit passes | 2026-11-03 |
| D1 | App stack: custom Laravel app | Matches the team's PHP/WordPress skills; publishing stays behind an adapter | 2026-11-03 |
| D11 | Approval link: a Laravel signed URL per review batch, valid 30 days like the inbox link (D9); one decision per post per batch; reminders and escalation by e-mail only; `multi_level` behaves like `required` for now | No login for clients; SMS would mean a paid service (D2); nobody has asked for two approval levels yet | 2026-11-03 |
| D13 | What goes to a platform is one post with every profile language in order (EL then EN for most clients), a blank line between, the hashtags once at the end; the platform limit is checked on the combined text | Clients here post bilingual captions in one post; separate posts per language would double the feed | 2026-11-03 |
| D14 | OAuth connect flow written with the HTTP client, no Socialite (TikTok and Business Profile would need community providers anyway); staff pick which Page, creator or location is the client's after the login; a TikTok post is published only as SELF_ONLY until `TIKTOK_AUDITED=true`, otherwise it goes to Manual-Needed; TikTok options (privacy, comments, duet, stitch, commercial disclosure, consent) and GBP event/offer fields live in `posts.settings` | Three small exchanges beat a dependency; the agency manages many Pages under one login; TikTok forces private posts before the audit and requires those controls in any composer | 2026-11-03 |
| D3 | Hosting: a subdomain on Panos's Plesk server (setup in `docs/pilot-setup.md`): MariaDB, database queue and cache run by a per-minute `queue:work` task instead of Redis and Horizon; media on the server's disk behind signed links for the pilot, an EU S3-compatible bucket before more clients are added | Panos already has hosting; one less account before the pilot | 2026-11-03 |
| D4 | First pilot client: Fuse Pharmacy (code `FUSE`, type `brand`) | Panos's call | 2026-11-03 |
| D10 | Post state machine is a PHP enum (`App\Posts\PostState`) with a transitions map, not the spatie/laravel-model-states package named in the scaffold proposal | Nine states and a dozen transitions fit in 60 lines; no dependency, no magic | 2026-11-03 |
| D9 | Inbox upload links are Laravel signed URLs that expire after 30 days, shown on the client's assets page; there is no per-link revocation (rotating APP_KEY invalidates all) | No login for clients was the requirement; a token table can be added if a link leaks | 2026-11-03 |
| D8 | Brand profile stored as one JSON column (`clients.profile`) in the example.yaml shape and edited as YAML text in the staff form; `Client::toProfileArray()` feeds prompts and drivers | Smallest complete version; a per-field form can replace the textarea when non-technical staff edit profiles | 2026-11-03 |
| D7 | Laravel 13 on PHP 8.3, Pest for tests, Breeze (Blade) for staff auth without public registration, Horizon on Redis for queues | Current stable at kickoff; smallest stack that covers the scaffold proposal | 2026-11-03 |
| D2 | Publishing layer: direct drivers built in-house (Meta Graph API, TikTok Content Posting API, Google Business Profile API); no paid service | User's call: no paid third-party services (Claude API and hosting are fine). The cost is calendar time: Phase 0 approvals become the critical path | 2026-11-03 |
| D9 | Trend research: Claude API with its web search tool writes the trend brief the batch planner uses; no scraping services (ScrapeCreators, Apify) and no browser-cookie scrapers in the app. A brief made elsewhere (for example a `/last30days` run) can be passed in with `--brief` | Keeps D2's "no paid third-party services" rule; the last30days tool Panos shared needs ScrapeCreators for TikTok and Instagram and browser sessions for X. Official Instagram hashtag search through our own Meta app is the next source once that app exists | 2026-11-03 |
| D10 | The interface speaks English and Greek: a switch per login (and per browser for guests), client-facing pages and mails default to the client's first profile language. Translations live in `lang/el.json`; a test fails when a string has no Greek | Panos asked for Greek with a choice to change (2026-11-04); the staff and most clients are Greek speakers, the approval links reach client owners on their phones | 2026-11-04 |
| D15 | **Removed by D19.** Link-in-bio page on the client's own WordPress site (the public `/bio/{slug}` page stays as the fallback): connected with a WordPress application password, the per-application, revocable REST credential, never the login password (WordPress has no OAuth), stored encrypted like a token; the page is created once and overwritten on every Publish | Panos's card answer (2026-11-04): clients want the page on their own domain; the agency site and a Social Ops-only page were the alternatives | 2026-11-04 |

| D16 | Organize mode: Social Ops organizes the work and the team posts in the apps by hand. Everything that posts through our drivers or reads back from the platform APIs is off behind `FEATURE_PUBLISHING` (`config/features.php`); the code stays. Posts go Approved → Scheduled → "Mark published" by hand; Failed, Manual-needed and Withdrawn have no buttons while the flag is off | Panos's call (2026-11-04): "we no longer have as goal to post on the socials", keep the code "maybe we will need them in the future"; the UI breathes | 2026-11-04 |
| D18 | Claude works through the MCP connector, not the server-side API: `get-planning-brief` hands Claude the profile, quota, window and prompt, Claude researches the trends in the chat (last30days skill or web search) and plans, `save-plan` files the Drafts and the review sheet. The server-side Claude buttons stay in the code behind `FEATURE_CLAUDE_API` (off) | Panos's call (2026-11-04): "The claude from now on should work with a connection mcp rather than api. If things go well then we converted to api again" | 2026-11-04 |
| D17 | Platforms: Instagram, Facebook, TikTok and LinkedIn. Google Business Profile removed from the code and the interface (driver, OAuth provider, reviews, the Performance API month, the event and offer fields). LinkedIn has no driver: it is planned, captioned and approved in Social Ops (feed, carousel and reel formats, 3,000 characters) and posted by hand | Panos's call (2026-11-04): "remove the google my business completely. Keep Facebook, Instagram, Tiktok and we add linkedin" | 2026-11-04 |
| D19 | Link in bio removed completely: the public `/bio/{slug}` page, the WordPress page of D15 (`App\Bio`, the box on the client form, its routes and texts). A migration deletes the stored WordPress application passwords. A `links` page already published on a client's site stays there until someone deletes it in WordPress | The team's call (2026-11-05): "delete the link in bio completely"; the app organizes the posts, the bio page is not part of that | 2026-11-05 |
| D20 | Recycle bin per client: deleting a post (the post page or the list's bulk delete) soft-deletes it (`posts.deleted_at`, `deleted_by`); it leaves every list, the approval links and the tools, and keeps its captions, media, notes and approval history. The client's Recycle bin tab restores it as it was or deletes it for good, one post or all of them. Nothing empties the bin on its own. Published posts still cannot be deleted. With posting on, a Scheduled post restored after its time comes back Approved, so a restore never publishes by itself, and a publish job already queued leaves a binned post alone. An approval whose waiting posts were all deleted reminds nobody and closes once overdue; a post restored in time waits in it again, one restored after it closed comes back a Draft to send again | The team's call (2026-11-05): "If someone deletes a post it goes to recycle bin and can restore if they want"; no automatic emptying because nobody asked for it and it would delete work silently | 2026-11-05 |
| D21 | The last30days skill (Claude's trend research while planning, D9 and D18) lives as a copy in the repo, `.claude/skills/last30days` (MIT, without its demo media), so every Claude Code session on the repo has it from the start: the cloud sessions and the scheduled worker included. A daily GitHub workflow (`.github/workflows/last30days-update.yml`) copies the newest version and, when it changed, opens one PR with Pint and the tests run, for Panos to read and merge; a closed version is not offered again | Panos asked for the latest version automatically. Cloud sessions load no plugins from the repo's settings and read skills before a start hook runs, and fetching the newest unread copy into every session (the worker can write posts through the connector) was refused by the session's safety check. A reviewed copy updated by PR keeps a human on every change. The app and the server never run it | 2026-11-06 |
